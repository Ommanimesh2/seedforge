# v2.7.0 — Trust release

The Wave 1 release from `PATHWAY.md`. Theme: **make the 60-second
demo not break on real-world schemas**, and align the README's claims
with what the tool actually does.

## What changed

### CHECK-constraint enum picking now handles real Postgres output

Before v2.7.0, seedforge's CHECK extractor handled `IN (...)` and the
simple `ANY (ARRAY[...])` shape, but it returned `null` on the form
Postgres actually emits via `pg_get_constraintdef`:

```
((order_type)::text = ANY ((ARRAY['PURCHASE'::character varying, …])::text[]))
```

The cast wrapper `(ARRAY[…])::text[]` adds an extra parenthesis the
old regex wouldn't tolerate. Result: every CHECK-constrained column
on real-world fintech schemas (`order_type`, `current_status`,
`order_sub_type`, …) fell through to faker lorem and tripped
`SF4001` constraint violations.

The new extractor:

- Walks balanced brackets/parens instead of single-pattern matching.
- Recognises the cast-wrapped form, the nullable `IS NULL OR …`
  guard, plain `IN (…)`, OR-chains, and embedded apostrophes.
- Rejects non-enum-looking IN lists (e.g. `IN (1,2,3)` is a range
  check, not an enum, and stays unmapped).

MySQL's `CHECK_CLAUSE` extractor was unified onto the same shared
function so all three dialects use one parser. SQLite already did.

E2e coverage in `src/__tests__/e2e/check-constraints.e2e.test.ts`
verifies generated rows respect the constraint against a real
Postgres 16 testcontainer.

### JPA real-world hardening (DDD codebases)

Previous versions only followed `@ManyToOne` / `@OneToOne` for FKs,
required all enums and entities to live in the user-specified
directory, and tripped on common Lombok/Hibernate idioms. On Curie's
transactions-service that produced **8 tables, 0 FKs, all enums
placeholder**.

v2.7.0 adds:

- **Project-root scan for enums.** When the user points at
  `domain/entity/`, seedforge walks up to find `src/main/java` (or
  `pom.xml` / `build.gradle`) and scans the whole tree for enum
  value-objects. Sibling-package enums (`commons/valueobject/`) now
  resolve to their real constants.
- **`@MappedSuperclass` field inheritance.** Subclasses that
  `extends BaseEntity` now correctly inherit `@Id`, timestamps, and
  any other declared fields.
- **ID-based FK inference.** When a column matches `<base>_id` of
  type UUID/BIGINT/INTEGER and an entity exists whose table name is
  `<base>` (or `<base>s`), an FK is inferred. This is the modern
  DDD pattern (raw UUID references, no `@ManyToOne`). Disable with
  `--no-id-fk-inference` if you store loose UUID references that
  shouldn't be FKs.
- **Annotation parser fixes:** balanced-paren scanning for
  `@Table(name="x", uniqueConstraints={@UniqueConstraint(...)})`,
  dotted nested annotations like `@EqualsAndHashCode.Include`,
  `class X extends Y implements Z`, and Java enums with constructor
  args (`AMC_FEED(3), AMFI(2);`).

Validated against Curie's actual codebase: 0 FKs → 9 FKs across 6
tables, all enums show real constants instead of placeholders.

E2e coverage in `src/__tests__/e2e/jpa-real-world.e2e.test.ts`
against a vendored Curie-style fixture in
`src/__tests__/e2e/fixtures/jpa-real-world/`.

### `seedforge inspect` subcommand + compatibility report

`--inspect` was a flag; v2.7.0 promotes it to a subcommand and adds
a compatibility report.

```bash
seedforge inspect --jpa ./src/main/java/com/example/entities/
```

Output now includes a per-table verdict:

- **`ok`** — seedforge will produce realistic, valid rows.
- **`risky`** — generation will succeed but some columns may be low
  fidelity (unknown types, free-text without constraints).
- **`blocked`** — generation cannot proceed (no PK, ungeneratable
  required column).

Each verdict carries structured reason codes (`MISSING_PRIMARY_KEY`,
`UNGENERATABLE_COLUMN`, `UNKNOWN_TYPE`, `UNCONSTRAINED_TEXT`) so CI
scripts can act on them. `--json` emits the structured form.

Legacy `--inspect` still works, with a soft deprecation note on
stderr (suppressed by `--quiet`).

E2e coverage in `src/__tests__/e2e/inspect-subcommand.e2e.test.ts`.

### Auto-discovery (suggest, don't choose)

Bare `seedforge` from a project root now walks the cwd for schema
sources and either (a) uses `DATABASE_URL` from env if set, or (b)
prints a list of detected sources and exits non-zero with explicit
options:

```
$ seedforge
seedforge: no schema source specified.

Detected schema sources in this project:
  • Live DB:  postgres://***@localhost:5432/myapp_dev — from .env
  • Prisma:   prisma/schema.prisma

Run one of:
  seedforge --db "postgres://localhost:5432/myapp_dev"
  seedforge --prisma prisma/schema.prisma
```

Discovery never silently picks between sources of different fidelity
(live DB vs. parser). The user always chooses. `--no-auto` reverts
to the previous SF5017 error path for users who pin explicit flags.

Detection signals:
- `prisma/schema.prisma` → Prisma
- `package.json` deps include `drizzle-orm` + `pgTable(`/`mysqlTable(`/`sqliteTable(` calls in `src/**/*.ts` → Drizzle
- `package.json` deps include `typeorm` + `@Entity()` in `src/**/*.ts` → TypeORM
- `pom.xml` / `build.gradle` + `@Entity` in `src/main/java/**` → JPA
- `DATABASE_URL` in env or `.env*`
- `docker-compose.yml` with a `postgres` / `mysql` service (informational)

E2e coverage in `src/__tests__/e2e/auto-discovery.e2e.test.ts`
with six fixture projects spanning every detection rule.

### README rewrite + snippets test

The README now leads with the wedge sentence ("Stop maintaining
brittle seed scripts.") and an `npx` one-liner. Feature breadth moves
below the fold. New sections:

- **When to use `--db` vs. a parser flag.** Live DB = fidelity, parser
  = portability. Explicit framing replaces silent defaults.
- **Auto-discovery.** Documents the new bare-`seedforge` UX.
- **How seedforge compares.** Side-by-side with Faker / Mockaroo /
  hand-rolled SQL scripts. Anchors the wedge ("zero-config relational
  seeding from real schemas").

Code blocks intended to be runnable are tagged with the
`seedforge-test` info string. The new
`src/__tests__/e2e/readme-snippets.e2e.test.ts` extracts every
tagged block and executes it against a temp SQLite DB. If a
copy-paste from the README ever stops working, this test fails
before the regression ships.

### Parser strategy lock-in

Written decision (no code change): the native parser set is
**Prisma + Drizzle + TypeORM + JPA**. No new natives until those
four are bulletproof on real-world codebases. Other ORMs (GORM,
SQLAlchemy, Django, ActiveRecord, EF Core, Sequelize) connect via
`--db` after running migrations; community plugins fill in
post-v3.

DDL fallback (`seedforge --ddl <path>`) is deferred to a future
release per third-reviewer guidance — live DB is the adoption wedge,
DDL parsing is a portability/CI workflow that should never be a
silent fallback. See `.planning/v2/PATHWAY.md` for the deferred
list.

## Breaking changes

None. The legacy `--inspect` flag still works (with a soft
deprecation note). Inline `prisma/schema.prisma` auto-detection now
requires the user to declare an output target (`--output` or
`--dry-run`) — bare `seedforge` runs from a project with a Prisma
schema now go through auto-discovery instead. Users who relied on
the old auto-detect should add `--output seed.sql` or pass
`--prisma` explicitly.
