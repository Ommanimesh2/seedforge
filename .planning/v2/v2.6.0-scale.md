# v2.6.0 — Scale & Performance (`--fast` streaming)

Closes Phase 9 (Scale & Performance) and formally marks Phase 1 (Stem Scorer) as shipped.

## What changed

### Fused streaming `--fast` path (flat memory)

Before v2.6.0, `--fast` built the full generation result in memory and then streamed it out to PostgreSQL COPY. The generator was row-by-row, but the pipeline still buffered every row into a `GenerationResult` before insertion, so memory scaled with row count.

v2.6.0 introduces a **fused generate-and-insert pipeline**:

- `generateAndStream(schema, plan, client, config, consumer)` walks the insert plan one table at a time and hands each table's row generator directly to an output consumer.
- Only tables that participate in self-referencing FKs or cycle-broken deferred edges retain their rows in memory; every other table streams through and stays flat.
- Foreign-key propagation happens via an async-generator return value that carries the final PK tuples to the reference pool once the consumer drains the stream.

Concretely: a 1M-row flat table now runs with near-constant RSS instead of linear growth.

### PostgreSQL: streaming COPY

`src/output/executors/pg-copy-streaming.ts` wraps the new orchestrator with a `pg-copy-streams` consumer:

- Peeks the first row to derive the column list, then feeds every subsequent row through `Readable.from(asyncGen)` + `pipeline()` — backpressure is honored by the Node stream machinery.
- One `BEGIN`/`COMMIT` per table; `SF4001` on COPY failure with automatic `ROLLBACK`.
- Sequences reset after all tables complete, same as the non-streaming path.

### MySQL: `LOAD DATA LOCAL INFILE` streaming

`src/output/executors/mysql-load-data.ts` mirrors the PG streaming consumer for MySQL:

- Emits tab-delimited TSV (`\t` field terminator, `\\` escape, `\n` line terminator) with `\N` for NULL.
- Escape rules: `\\` → `\\\\`, `\t` → `\\t`, `\n` → `\\n`, `\r` → `\\r`, `\0` → `\\0`. Datetimes as `YYYY-MM-DD HH:MM:SS`. Arrays/objects serialize as JSON, then escape. Buffers escape byte-wise.
- Feeds the TSV stream into `mysql2`'s `infileStreamFactory` query option — the server reads the generator output byte-for-byte as though it were a local file.
- Requires the server to have `local_infile=ON` (mysql2's client capability flag is on by default).
- `AUTO_INCREMENT` is reset per table after all inserts complete.

### `--fast` is no longer PG-only

- The `SF5019` "PostgreSQL only" validation was relaxed: `--fast` now works on Postgres **and** MySQL. SQLite still errors out — there is no streaming bulk-load protocol to plug into.
- Both CLI entrypoints (`src/cli.ts`) and the programmatic API (`src/core/pipeline.ts`) dispatch to the correct fused pipeline when `--fast` + direct mode + a PG/MySQL connection are all present.

### Benchmark suite

`bench/` is new:

- `bench/fixtures.ts` — three fixtures: **narrow** (1 table × 5 cols), **wide** (1 table × 24 cols), **complex** (4 tables with FK chain + self-ref).
- `bench/run.ts` — runs the matrix `{fixtures} × {10k, 100k} × {pg-insert, pg-copy, mysql-load}` against PG + MySQL testcontainers and prints a comparison table with wall time, rows/sec, and RSS growth per run.
- `npm run bench` runs all fixtures; `npm run bench -- wide` runs one. Not wired into CI — intended for local regression tracking and release notes.

## Breaking changes

None. `--fast` now additionally supports MySQL — previously it only errored. Existing PG `--fast` workflows are unchanged in behavior but now run through the streaming pipeline so memory stays flat at large row counts.
